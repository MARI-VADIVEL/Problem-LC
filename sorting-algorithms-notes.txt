
========================================
THEORY: Sorting Basics
========================================

Explanation:
Sorting means arranging the elements in some order. Most of the time we sort from small to big.

Example:
[5,2,8,1] -> [1,2,5,8]


========================================
THEORY: Ascending Order
========================================

Explanation:
Ascending means the smaller value comes first and the bigger value comes later.

Example:
[4,1,3,2] -> [1,2,3,4]


========================================
THEORY: Descending Order
========================================

Explanation:
Descending is the opposite of ascending. We start with the biggest value.

Example:
[4,1,3,2] -> [4,3,2,1]


========================================
THEORY: Bubble Sort
========================================

Explanation:
Compare two nearby elements. If the left one is bigger, swap them. By doing this again and again, bigger elements move to the end.

Example:
[5,2,1] -> [2,5,1] -> [2,1,5] -> [1,2,5]


========================================
THEORY: Bubble Sort Pass
========================================

Explanation:
One pass means going through the array once and comparing the neighbouring elements. Usually the biggest unsorted value reaches the end.

Example:
[4,2,3] -> after a pass, 4 moves to the end


========================================
THEORY: Optimized Bubble Sort
========================================

Explanation:
We can use a boolean variable to check whether a swap happened. If no swap happened, the array is already sorted and we can stop.

Example:
[1,2,3,4] -> no swap -> stop


========================================
THEORY: Bubble Sort Complexity
========================================

Explanation:
Bubble Sort normally takes O(n^2) time because many comparisons are done. If the array is already sorted and we use the swap check, it can take O(n).

Example:
[1,2,3,4,5] -> only one pass is needed


========================================
THEORY: Selection Sort
========================================

Explanation:
Find the smallest element from the unsorted part and put it at the beginning. Then repeat for the remaining part.

Example:
[4,2,1,3] -> find 1 -> [1,2,4,3]


========================================
THEORY: Selection Sort Minimum
========================================

Explanation:
In every round, we search for the minimum value and remember its index. At the end of the round, we swap it with the current position.

Example:
[5,3,2,4] -> minimum is 2


========================================
THEORY: Selection Sort Complexity
========================================

Explanation:
Selection Sort always searches the remaining elements, so it takes O(n^2) time. It does not become much faster even when the array is already sorted.

Example:
[1,2,3,4] -> still performs comparisons


========================================
THEORY: Insertion Sort
========================================

Explanation:
Take one element and insert it into the correct place in the already sorted part of the array.

Example:
[5,2,4] -> [2,5,4] -> [2,4,5]


========================================
THEORY: Insertion Sort Shifting
========================================

Explanation:
Before inserting the current element, bigger elements are shifted one position to the right.

Example:
[2,5,4] -> move 5 right -> insert 4


========================================
THEORY: Insertion Sort Complexity
========================================

Explanation:
Insertion Sort can take O(n^2) in the worst case. When the array is almost sorted, it can work much faster.

Example:
[1,2,3,5,4] needs only a small shift


========================================
THEORY: Insertion Sort Stability
========================================

Explanation:
Insertion Sort can keep equal elements in the same order they were originally in. This is called stable sorting.

Example:
[A(2),B(2)] -> [A(2),B(2)]


========================================
THEORY: Merge Sort
========================================

Explanation:
Merge Sort first breaks the array into smaller parts. Then it sorts and joins those parts back together.

Example:
[4,1,3,2] -> [4,1] [3,2] -> [1,4] [2,3] -> [1,2,3,4]


========================================
THEORY: Merge Sort Divide
========================================

Explanation:
We keep dividing the array into two parts until each part has only one element.

Example:
[8,4,2,6] -> [8,4] [2,6] -> [8][4][2][6]


========================================
THEORY: Merge Sort Merge
========================================

Explanation:
After dividing, we compare the elements from the two sorted parts and put the smaller one into the result.

Example:
[1,4] and [2,3] -> [1,2,3,4]


========================================
THEORY: Merge Sort Complexity
========================================

Explanation:
Merge Sort takes O(n log n) time. The array is divided into log n levels and every level processes all n elements.

Example:
8 elements -> about 3 levels of division


========================================
THEORY: Merge Sort Space
========================================

Explanation:
Normal Merge Sort needs an extra array while merging the two parts. So its extra space is O(n).

Example:
For a bigger array, temporary space is used during merging.


========================================
THEORY: Merge Sort Stability
========================================

Explanation:
Merge Sort can be stable if we take the element from the left side first when both values are equal.

Example:
[A(2),B(2)] -> A stays before B


========================================
THEORY: Quick Sort
========================================

Explanation:
Choose one element as a pivot. Put smaller elements on one side and bigger elements on the other side. Then repeat the same process for both parts.

Example:
[5,2,8,1] with pivot 5 -> [2,1] 5 [8]


========================================
THEORY: Quick Sort Pivot
========================================

Explanation:
The pivot is the element we use to divide the array. It can be the first element, last element, middle element, or chosen randomly.

Example:
[4,2,7,1] -> choose 4 as pivot


========================================
THEORY: Quick Sort Partition
========================================

Explanation:
Partitioning means rearranging the elements around the pivot. After partitioning, the pivot is placed in its correct position.

Example:
[4,2,7,1] -> [2,1] 4 [7]


========================================
THEORY: Quick Sort Complexity
========================================

Explanation:
Quick Sort usually takes O(n log n), but a bad pivot can make it O(n^2). Choosing a good pivot helps avoid very unbalanced parts.

Example:
[1,2,3,4,5] with a bad pivot can create unbalanced partitions


========================================
THEORY: Quick Sort Space
========================================

Explanation:
Quick Sort uses recursion, so it needs stack space for the function calls. Balanced partitions usually need about O(log n) stack space.

Example:
Balanced split -> fewer recursive calls


========================================
THEORY: Heap Sort
========================================

Explanation:
Heap Sort first makes a heap. Then it takes the largest element from the heap and puts it at the end of the array.

Example:
[4,1,3,2] -> build max heap -> move largest to end


========================================
THEORY: Max Heap
========================================

Explanation:
In a Max Heap, the parent is greater than or equal to its children. So the biggest value stays at the top.

Example:
[4,2,3,1] -> 4 is at the root


========================================
THEORY: Min Heap
========================================

Explanation:
In a Min Heap, the parent is smaller than or equal to its children. So the smallest value stays at the top.

Example:
[1,2,3,4] -> 1 is at the root


========================================
THEORY: Heap Sort Complexity
========================================

Explanation:
Building and repeatedly adjusting the heap gives Heap Sort O(n log n) time.

Example:
[5,3,1,4,2] -> repeatedly remove the maximum


========================================
THEORY: Heap Sort Space
========================================

Explanation:
Heap Sort can work directly inside the original array, so it uses O(1) extra array space.

Example:
The heap is created inside the same array.


========================================
THEORY: Counting Sort
========================================

Explanation:
Instead of comparing elements, Counting Sort counts how many times each value appears and then creates the sorted array.

Example:
[2,1,2,3] -> counts -> [1,2,2,3]


========================================
THEORY: Counting Sort Range
========================================

Explanation:
Counting Sort works well when the numbers are in a small range. We create an array based on that range.

Example:
[1,4,2,1] -> values are only from 1 to 4


========================================
THEORY: Counting Sort Complexity
========================================

Explanation:
Counting Sort takes O(n+k), where n is the number of elements and k is the range of values.

Example:
100 elements with values from 0 to 50 -> n=100, k=51


========================================
THEORY: Radix Sort
========================================

Explanation:
Radix Sort sorts numbers digit by digit. It normally starts from the last digit and moves toward the first digit.

Example:
[170,45,75,90] -> sort by units, then tens, then hundreds


========================================
THEORY: Radix Sort Digits
========================================

Explanation:
Each round groups numbers based on one digit. The previous ordering is kept while processing the next digit.

Example:
45 and 75 both have units digit 5, so their previous order is maintained.


========================================
THEORY: Radix Sort Complexity
========================================

Explanation:
Radix Sort depends on the number of digits. Its common complexity is O(d(n+k)), where d is the number of digits.

Example:
For 4-digit numbers, d is 4.


========================================
THEORY: Bucket Sort
========================================

Explanation:
Bucket Sort puts values into different buckets. Each bucket is sorted separately and then all buckets are joined.

Example:
[0.42,0.32,0.75] -> put values into buckets -> sort -> combine


========================================
THEORY: Bucket Sort Distribution
========================================

Explanation:
The values are divided into buckets based on their range. Values that are close to each other usually go into the same bucket.

Example:
0.1 and 0.2 can go into the same bucket range.


========================================
THEORY: Bucket Sort Complexity
========================================

Explanation:
Bucket Sort can be very fast when the values are distributed evenly. Its average performance can be close to O(n).

Example:
Uniformly distributed values usually create smaller buckets.


========================================
THEORY: Stable Sorting
========================================

Explanation:
A stable sort does not change the order of equal elements. This is useful when objects have more than one property.

Example:
[A(80),B(80)] -> A remains before B


========================================
THEORY: Unstable Sorting
========================================

Explanation:
An unstable sort may change the order of elements that have the same value.

Example:
[A(80),B(80)] could become [B(80),A(80)]


========================================
THEORY: In-place Sorting
========================================

Explanation:
An in-place algorithm changes the original array instead of creating another large array for the result.

Example:
Selection Sort rearranges the same array.
