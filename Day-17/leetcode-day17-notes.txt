COMMIT 1 - Add Edit Distance problem statement and operation rules
============================================================
LeetCode 72 - Edit Distance

Problem:
Convert word1 into word2 using the minimum number of operations.

Allowed operations:
1. Insert a character
2. Delete a character
3. Replace a character

Example:
word1 = horse
word2 = ros

Answer = 3

============================================================
COMMIT 2 - Add Edit Distance recursive thinking
============================================================
Edit Distance - Recursive Thinking

Define solve(i,j) as the minimum operations needed to convert
word1 starting from index i into word2 starting from index j.

At every position compare the two characters.

If they are different, there are three choices:
Insert
Delete
Replace

============================================================
COMMIT 3 - Add Edit Distance base cases
============================================================
Edit Distance - Base Cases

If word1 is completely processed, the remaining characters of
word2 must all be inserted.

If word2 is completely processed, the remaining characters of
word1 must all be deleted.

Base cases:
i == word1.length()
j == word2.length()

============================================================
COMMIT 4 - Add Edit Distance insert delete replace transitions
============================================================
Edit Distance - Transitions

If characters are different:

insert = solve(i, j + 1)
delete = solve(i + 1, j)
replace = solve(i + 1, j + 1)

Current answer:
1 + minimum(insert, delete, replace)

If characters are equal:
solve(i + 1, j + 1)

============================================================
COMMIT 5 - Add Edit Distance recursive Java solution
============================================================
Edit Distance - Recursive Solution

The recursive solution directly represents the three possible
operations.

It is useful for understanding the problem before introducing DP.

The main drawback is repeated calculation of the same states.

============================================================
COMMIT 6 - Explain overlapping subproblems in Edit Distance
============================================================
Edit Distance - Overlapping Subproblems

Different recursive paths can reach the same state solve(i,j).

Calculating the same state repeatedly makes the recursive
solution inefficient.

Dynamic Programming stores the result of each state so it is
calculated only once.

============================================================
COMMIT 7 - Add Edit Distance 2D DP state definition
============================================================
Edit Distance - 2D DP

dp[i][j] represents the minimum operations required to convert
the first i characters of word1 into the first j characters
of word2.

This converts the recursive problem into a table-based DP.

============================================================
COMMIT 8 - Add Edit Distance DP initialization
============================================================
Edit Distance - DP Initialization

dp[i][0] = i

Converting the first i characters into an empty string requires
deleting i characters.

dp[0][j] = j

Converting an empty string into the first j characters requires
inserting j characters.

============================================================
COMMIT 9 - Add Edit Distance optimized 1D DP solution
============================================================
Edit Distance - Space Optimization

The 2D DP table can be reduced to one dimension because each
state only needs values from the previous row and current row.

A variable called prev stores the previous diagonal value.

Time: O(n * m)
Space: O(m)

Use:

mid = left + (right - left) / 2

COMMIT 14 - Add Guess Number guess result handling
============================================================

guess(mid) == 0
The answer is mid.

guess(mid) == 1
The hidden number is greater than mid.
Move left to mid + 1.

guess(mid) == -1
The hidden number is smaller than mid.
Move right to mid - 1.

COMMIT 16 - Document Binary Search boundary handling
============================================================
Binary Search - Boundary Handling

The loop condition is:

left <= right

When the middle value is too small:
left = mid + 1

When the middle value is too large:
right = mid - 1

These updates prevent the same value from being checked again.

COMMIT 17 - Add Kth Missing Positive problem understanding
============================================================
LeetCode 1539 - Kth Missing Positive Number

Given a sorted array of positive integers, find the kth positive
integer that does not appear in the array.

Example:
arr = [2,3,4,7,11]
k = 5

Missing values:
1,5,6,8,9

Answer = 9

============================================================
COMMIT 18 - Add missing count formula for Kth Missing Positive
============================================================
Kth Missing Positive - Missing Count

At index i, the expected value without missing numbers is i + 1.

Therefore:

missing = arr[i] - (i + 1)

Example:
arr[3] = 7

missing = 7 - 4
        = 3

There are three missing positive numbers before 7.

============================================================
COMMIT 19 - Add Kth Missing Positive binary search condition
============================================================
Kth Missing Positive - Binary Search

We need the first index where:

arr[mid] - (mid + 1) >= k

If the missing count is smaller than k:
move right.

Otherwise:
move left.

This is a lower-bound style binary search.

============================================================
COMMIT 20 - Add Kth Missing Positive final answer formula
============================================================
Kth Missing Positive - Final Formula

After binary search, left represents how many array values are
before the kth missing number.

The answer is:

answer = k + left

Example:
k = 5
left = 4

answer = 9

COMMIT 24 - Add Maximum Fruits sliding window concept
============================================================
Maximum Fruits - Sliding Window

Because fruit positions are sorted, a consecutive range of
positions can be represented as a window.

Expand the right side and maintain the total number of fruits.

If the walking distance becomes greater than k, move the left
side forward.

============================================================
COMMIT 25 - Add fruit range movement calculation
============================================================
Maximum Fruits - Movement Calculation

For a window [left, right]:

leftDistance = startPos - left
rightDistance = right - startPos

If the entire range is on the left:
steps = startPos - left

If the entire range is on the right:
steps = right - startPos

============================================================
COMMIT 26 - Add left-first and right-first movement formulas
============================================================
Maximum Fruits - Crossing the Starting Position

When the window crosses startPos:

left first:
2 * leftDistance + rightDistance

right first:
leftDistance + 2 * rightDistance

Take the minimum of these two values.

============================================================
COMMIT 27 - Add Maximum Fruits window expansion logic
============================================================
Maximum Fruits - Window Expansion

For every right position:
1. Add its fruit count to the current sum.
2. Check whether the current range can be visited within k steps.
3. Keep the largest valid sum.

============================================================
COMMIT 28 - Add Maximum Fruits window shrinking logic
============================================================
Maximum Fruits - Window Shrinking

If the current window needs more than k steps:

Remove fruits at the left position.
Move left forward.
Repeat until the window becomes valid.

============================================================

COMMIT 32 - Add distance condition as numeric range

The condition:

can be rewritten as:

x - d <= y <= x + d

Therefore, for every x, we only need to determine whether arr2
contains a value inside this range.

COMMIT 33 - Add sorting for Distance Value optimization
============================================================
Distance Value - Sorting

Sort arr2 first.

Once arr2 is sorted, binary search can quickly find the first
value greater than or equal to x - d.

COMMIT 34 - Add lower-bound binary search logic
============================================================
Distance Value - Lower Bound

Search for the first arr2 value satisfying:

arr2[mid] >= x - d

After the search:
- If no such value exists, x is valid.
- If the value is greater than x + d, x is valid.
- Otherwise a nearby value exists.

Process fruits from left to right.

For every fruit quantity, choose the leftmost available basket

If no basket can hold it, the fruit remains unplaced.

COMMIT 39 - Add used basket handling
============================================================

Once a basket is used, it cannot be used again.

COMMIT 40 - Add Fruits Into Baskets II basic Java solution
============================================================
Fruits Into Baskets II - Basic Solution

For each fruit:
1. Scan baskets from left to right.
2. Find the first available basket with enough capacity.
3. Mark it as used.
4. If no basket works, increment the unplaced count.

Basic complexity:
O(n^2)

COMMIT 41 - Add segment tree optimization concept
============================================================
Fruits Into Baskets II - Segment Tree

The basic solution scans every basket.

A segment tree can store the maximum basket capacity in each
range.

If a range maximum is smaller than the current fruit quantity,
that entire range can be skipped.

============================================================
COMMIT 42 - Add segment tree maximum-value representation
============================================================
Segment Tree - Maximum Capacity

Each tree node stores the maximum capacity among its range.

This allows us to quickly determine whether a valid basket exists
inside a range.

============================================================
COMMIT 43 - Add leftmost valid basket search
============================================================
Segment Tree - Leftmost Valid Basket

To find the leftmost valid basket:
1. If the current maximum is less than the fruit quantity, return -1.
2. Check the left child first.
3. If no valid basket exists there, check the right child.
4. Continue until reaching a leaf.

============================================================
COMMIT 44 - Add basket update operation
============================================================
Segment Tree - Basket Update

After using a basket, its capacity is set to -1.

The segment tree is then updated upward so every affected range
has the correct maximum value.

============================================================
Fruits Into Baskets II - Optimized Solution

Segment tree operations:
Build: O(n)

Overall:
Time: O(n log n)
