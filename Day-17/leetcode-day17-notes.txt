COMMIT 1 - Add Edit Distance problem statement and operation rules
============================================================
LeetCode 72 - Edit Distance

Problem:
Convert word1 into word2 using the minimum number of operations.

Allowed operations:
1. Insert a character
2. Delete a character
3. Replace a character

Example:
word1 = horse
word2 = ros

Answer = 3

============================================================
COMMIT 2 - Add Edit Distance recursive thinking
============================================================
Edit Distance - Recursive Thinking

Define solve(i,j) as the minimum operations needed to convert
word1 starting from index i into word2 starting from index j.

At every position compare the two characters.

If they are different, there are three choices:
Insert
Delete
Replace

============================================================
COMMIT 3 - Add Edit Distance base cases
============================================================
Edit Distance - Base Cases

If word1 is completely processed, the remaining characters of
word2 must all be inserted.

If word2 is completely processed, the remaining characters of
word1 must all be deleted.

Base cases:
i == word1.length()
j == word2.length()

============================================================
COMMIT 4 - Add Edit Distance insert delete replace transitions
============================================================
Edit Distance - Transitions

If characters are different:

insert = solve(i, j + 1)
delete = solve(i + 1, j)
replace = solve(i + 1, j + 1)

Current answer:
1 + minimum(insert, delete, replace)

If characters are equal:
solve(i + 1, j + 1)

COMMIT 5 - Add Edit Distance recursive Java solution
============================================================
Edit Distance - Recursive Solution

The recursive solution directly represents the three possible
operations.

It is useful for understanding the problem before introducing DP.

The main drawback is repeated calculation of the same states.

============================================================
COMMIT 6 - Explain overlapping subproblems in Edit Distance
============================================================
Edit Distance - Overlapping Subproblems

Different recursive paths can reach the same state solve(i,j).

Calculating the same state repeatedly makes the recursive
solution inefficient.

Dynamic Programming stores the result of each state so it is
calculated only once.

============================================================
COMMIT 7 - Add Edit Distance 2D DP state definition
============================================================
Edit Distance - 2D DP

dp[i][j] represents the minimum operations required to convert
the first i characters of word1 into the first j characters
of word2.

This converts the recursive problem into a table-based DP.

============================================================
COMMIT 8 - Add Edit Distance DP initialization
============================================================
Edit Distance - DP Initialization

dp[i][0] = i

Converting the first i characters into an empty string requires
deleting i characters.

dp[0][j] = j

Converting an empty string into the first j characters requires
inserting j characters.

============================================================
COMMIT 9 - Add Edit Distance optimized 1D DP solution
============================================================
Edit Distance - Space Optimization

The 2D DP table can be reduced to one dimension because each
state only needs values from the previous row and current row.

A variable called prev stores the previous diagonal value.

Time: O(n * m)
Space: O(m)

============================================================
COMMIT 10 - Document Edit Distance time and space complexity
============================================================
Edit Distance - Complexity

2D DP:
Time: O(n * m)
Space: O(n * m)

Optimized 1D DP:
Time: O(n * m)
Space: O(m)

The 1D version keeps the same time complexity while reducing
memory usage.

LeetCode 374 - Guess Number Higher or Lower

The hidden number is between 1 and n.

The guess API returns:
0  -> correct
1  -> hidden number is higher
-1 -> hidden number is lower

This naturally forms a Binary Search problem.

============================================================
COMMIT 12 - Add Guess Number search range initialization
============================================================
Guess Number - Search Range

Start with:

left = 1
right = n

The complete possible range is initially available.

After every guess, one half of the range can be eliminated.

============================================================
COMMIT 13 - Add Guess Number midpoint calculation
============================================================
Guess Number - Midpoint

Use:

mid = left + (right - left) / 2

This is safer than:

(left + right) / 2

because it avoids unnecessary integer overflow.

============================================================
COMMIT 14 - Add Guess Number guess result handling
============================================================
Guess Number - Decision Rules

guess(mid) == 0
The answer is mid.

guess(mid) == 1
The hidden number is greater than mid.
Move left to mid + 1.

guess(mid) == -1
The hidden number is smaller than mid.
Move right to mid - 1.
