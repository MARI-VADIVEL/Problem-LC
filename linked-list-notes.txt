
========================================
LINKED LIST THEORY: Linked List Introduction
========================================

Explanation:
A linked list is a linear data structure made up of nodes. Each node stores data and a reference to another node. Unlike arrays, linked-list nodes do not have to be stored in contiguous memory.

Example:
Example: 10 -> 20 -> 30 -> null


========================================
LINKED LIST THEORY: Node
========================================

Explanation:
A node is the basic building block of a linked list. In a singly linked list, a node contains data and a reference called next that points to the following node.

Example:
Example: A node containing 10 can point to the node containing 20.


========================================
LINKED LIST THEORY: Head
========================================

Explanation:
The head is a reference to the first node of a linked list. It is the starting point for traversing the list.

Example:
Example: head -> 10 -> 20 -> 30 -> null


========================================
LINKED LIST THEORY: Tail
========================================

Explanation:
The tail is the last node in a linked list. Its next reference is null in a standard singly linked list.

Example:
Example: In 10 -> 20 -> 30 -> null, 30 is the tail.


========================================
LINKED LIST THEORY: Next Pointer
========================================

Explanation:
The next pointer stores the reference to the next node. It allows individual nodes to form a connected sequence.

Example:
Example: If node 10 points to node 20, then node10.next refers to node20.


========================================
LINKED LIST THEORY: Singly Linked List
========================================

Explanation:
A singly linked list contains nodes where every node points only to the next node. Traversal normally happens from the head toward the tail.

Example:
Example: 10 -> 20 -> 30 -> null


========================================
LINKED LIST THEORY: Doubly Linked List
========================================

Explanation:
A doubly linked list contains two references in each node: previous and next. This allows traversal in both forward and backward directions.

Example:
Example: null <- 10 <-> 20 <-> 30 -> null


========================================
LINKED LIST THEORY: Circular Linked List
========================================

Explanation:
In a circular linked list, the last node points back to an earlier node, commonly the head, instead of pointing to null.

Example:
Example: 10 -> 20 -> 30 -> 10


========================================
LINKED LIST THEORY: Circular Doubly Linked List
========================================

Explanation:
A circular doubly linked list combines backward and forward links with circular connections. The tail points to the head and the head points back to the tail.

Example:
Example: 10 <-> 20 <-> 30 where the ends are connected.


========================================
LINKED LIST THEORY: Linked List Memory
========================================

Explanation:
Linked-list nodes can be stored at different memory locations. References connect these locations to create the logical sequence.

Example:
Example: Nodes may physically be separated in memory while logically representing 10 -> 20 -> 30.


========================================
LINKED LIST THEORY: Linked List Traversal
========================================

Explanation:
Traversal means starting at the head and following next references until the required node or the end of the list is reached.

Example:
Example: To find 30 in 10 -> 20 -> 30, visit 10, then 20, then 30.


========================================
LINKED LIST THEORY: Linked List Search
========================================

Explanation:
Searching a linked list normally requires sequential traversal because nodes do not support direct index-based access.

Example:
Example: Finding the fifth node requires moving through previous nodes.


========================================
LINKED LIST THEORY: Linked List Access
========================================

Explanation:
Accessing an element at a specific position in a linked list takes O(n) time because the list must usually be traversed from the head.

Example:
Example: Finding index 4 requires following four links first.


========================================
LINKED LIST THEORY: Insert At Beginning
========================================

Explanation:
Insertion at the beginning is efficient because the new node can point to the current head and then become the new head.

Example:
Example: 20 -> 30 becomes 10 -> 20 -> 30.


========================================
LINKED LIST THEORY: Insert At End
========================================

Explanation:
Insertion at the end requires finding the tail when only a head reference is available. With a maintained tail reference, insertion can be O(1).

Example:
Example: 10 -> 20 becomes 10 -> 20 -> 30.


========================================
LINKED LIST THEORY: Insert At Position
========================================

Explanation:
Insertion at a particular position requires reaching the node before the insertion point and changing references appropriately.

Example:
Example: Insert 25 between 20 and 30 to get 10 -> 20 -> 25 -> 30.


========================================
LINKED LIST THEORY: Delete First Node
========================================

Explanation:
Deleting the first node is performed by moving the head reference to the second node. This operation takes O(1) time.

Example:
Example: 10 -> 20 -> 30 becomes 20 -> 30.


========================================
LINKED LIST THEORY: Delete Last Node
========================================

Explanation:
Deleting the last node in a singly linked list usually requires finding the node before the tail. Therefore it generally takes O(n) time without a previous pointer.

Example:
Example: 10 -> 20 -> 30 becomes 10 -> 20.


========================================
LINKED LIST THEORY: Delete At Position
========================================

Explanation:
Deleting a node at a specific position requires reaching the previous node and changing its next reference to skip the target node.

Example:
Example: 10 -> 20 -> 30 becomes 10 -> 30 when 20 is removed.


========================================
LINKED LIST THEORY: Update Node
========================================

Explanation:
Updating a linked-list node means changing the data stored in an existing node. The node must first be located through traversal unless its reference is already known.

Example:
Example: 20 can be changed to 25 without changing the links.


========================================
LINKED LIST THEORY: Reverse Linked List Theory
========================================

Explanation:
Reversing a linked list means changing the direction of every next reference. The original head becomes the new tail and the original tail becomes the new head.

Example:
Example: 10 -> 20 -> 30 becomes 30 -> 20 -> 10.


========================================
LINKED LIST THEORY: Iterative Reversal
========================================

Explanation:
Iterative reversal commonly uses previous, current, and next references. The next reference is saved before changing current.next so that the remaining list is not lost.

Example:
Example: Each node is gradually redirected toward the previous node.


========================================
LINKED LIST THEORY: Recursive Reversal
========================================

Explanation:
Recursive reversal processes the remaining list first and then connects the current node after the recursive result. The recursion eventually reaches the original tail.

Example:
Example: 1 -> 2 -> 3 can be reversed through recursive calls.


========================================
LINKED LIST THEORY: Middle Node
========================================

Explanation:
The middle node can be found efficiently using slow and fast pointers. Slow moves one step while fast moves two steps.

Example:
Example: In 1 -> 2 -> 3 -> 4 -> 5, slow reaches 3.


========================================
LINKED LIST THEORY: Fast Pointer
========================================

Explanation:
The fast pointer moves faster than the slow pointer, usually two nodes at a time. It is useful for finding the middle and detecting cycles.

Example:
Example: slow moves one node while fast moves two nodes.


========================================
LINKED LIST THEORY: Slow Pointer
========================================

Explanation:
The slow pointer normally moves one node at a time. When paired with a fast pointer, it can identify positions related to the middle or cycles.

Example:
Example: When fast reaches the end, slow is around the middle.


========================================
LINKED LIST THEORY: Cycle Detection Theory
========================================

Explanation:
A linked-list cycle occurs when following next references eventually returns to a previously visited node. Floyd's algorithm detects this using two pointers.

Example:
Example: 1 -> 2 -> 3 -> 4 -> 2 creates a cycle.


========================================
LINKED LIST THEORY: Floyd Cycle Detection
========================================

Explanation:
Floyd's algorithm moves slow by one step and fast by two steps. If a cycle exists, fast eventually meets slow.

Example:
Example: Two runners moving at different speeds around a circular track eventually meet.


========================================
LINKED LIST THEORY: Cycle Starting Point
========================================

Explanation:
After detecting a cycle using slow and fast pointers, resetting one pointer to the head and moving both one step at a time can locate the cycle's starting node.

Example:
Example: In 1 -> 2 -> 3 -> 4 -> 2, node 2 is the cycle start.


========================================
LINKED LIST THEORY: Remove Cycle
========================================

Explanation:
Removing a linked-list cycle requires identifying the cycle's starting point and changing the previous node's next reference to null.

Example:
Example: 1 -> 2 -> 3 -> 4 -> 2 can be changed to 1 -> 2 -> 3 -> 4 -> null.


========================================
LINKED LIST THEORY: Merge Sorted Linked Lists
========================================

Explanation:
Two sorted linked lists can be merged by repeatedly selecting the smaller current node. A dummy node can simplify the construction of the result.

Example:
Example: 1 -> 3 and 2 -> 4 become 1 -> 2 -> 3 -> 4.


========================================
LINKED LIST THEORY: Dummy Node
========================================

Explanation:
A dummy node is an extra temporary node placed before the result list. It simplifies insertion and merging because the result always has a previous node.

Example:
Example: dummy -> 1 -> 2 -> 3.


========================================
LINKED LIST THEORY: Linked List Intersection
========================================

Explanation:
Two linked lists intersect when their nodes share the same physical node reference. Comparing only values is not sufficient to identify an intersection.

Example:
Example: Both lists can eventually point to the same node containing 8.
