
========================================
THEORY: LC496 Problem Understanding
========================================

Explanation:
Next Greater Element I asks us to find, for every element in nums1, the first greater element appearing to its right in nums2. nums1 is guaranteed to contain elements from nums2.

Example:
Example: nums1=[4,1,2], nums2=[1,3,4,2] gives [-1,3,-1].


========================================
THEORY: LC496 Brute Force Approach
========================================

Explanation:
For every value in nums1, first locate the same value in nums2. Then scan elements to its right until finding the first value greater than it. If no greater value exists, return -1.

Example:
For 4 in [1,3,4,2], there is no greater element after 4, so the answer is -1.


========================================
THEORY: LC496 Why Brute Force Is Slow
========================================

Explanation:
The brute-force solution may repeatedly search nums2 for each nums1 element and then scan to the right. In the worst case this can take O(nums1.length * nums2.length) time.

Example:
Repeated scanning becomes inefficient when the arrays contain many elements.


========================================
THEORY: LC496 Next Greater Element Meaning
========================================

Explanation:
The word next means the first greater value encountered while moving from left to right after the current element. We must not skip a smaller greater candidate to find a later larger value.

Example:
For [2,5,3,7], the next greater element of 2 is 5, not 7.
