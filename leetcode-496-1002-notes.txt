
========================================
THEORY: LC496 Problem Understanding
========================================

Explanation:
Next Greater Element I asks us to find, for every element in nums1, the first greater element appearing to its right in nums2. nums1 is guaranteed to contain elements from nums2.

Example:
Example: nums1=[4,1,2], nums2=[1,3,4,2] gives [-1,3,-1].


========================================
THEORY: LC496 Brute Force Approach
========================================

Explanation:
For every value in nums1, first locate the same value in nums2. Then scan elements to its right until finding the first value greater than it. If no greater value exists, return -1.

Example:
For 4 in [1,3,4,2], there is no greater element after 4, so the answer is -1.


========================================
THEORY: LC496 Why Brute Force Is Slow
========================================

Explanation:
The brute-force solution may repeatedly search nums2 for each nums1 element and then scan to the right. In the worst case this can take O(nums1.length * nums2.length) time.

Example:
Repeated scanning becomes inefficient when the arrays contain many elements.


========================================
THEORY: LC496 Next Greater Element Meaning
========================================

Explanation:
The word next means the first greater value encountered while moving from left to right after the current element. We must not skip a smaller greater candidate to find a later larger value.

Example:
For [2,5,3,7], the next greater element of 2 is 5, not 7.


========================================
THEORY: LC496 Monotonic Stack Idea
========================================

Explanation:
A monotonic stack helps solve Next Greater Element problems efficiently. We process nums2 and maintain values whose next greater element has not been found yet.

Example:
When a larger value appears, it can resolve smaller values waiting in the stack.


========================================
THEORY: LC496 Decreasing Stack
========================================

Explanation:
For this problem, the stack is maintained in decreasing order from bottom to top. When the current number is greater than the stack top, the stack top has found its next greater element.

Example:
Processing [1,3,4,2], 3 causes 1 to get its next greater value as 3.


========================================
THEORY: LC496 Pop Operation
========================================

Explanation:
When nums2 contains a value greater than the stack top, repeatedly pop smaller values. The current value becomes the next greater element for every popped value.

Example:
If the stack contains [5,2] and current value is 7, both 2 and 5 can receive 7 as their next greater element if they are unresolved.


========================================
THEORY: LC496 HashMap Mapping
========================================

Explanation:
A HashMap stores the answer for each value in nums2. After processing nums2, we can directly look up the answer for every value in nums1.

Example:
Example mapping can contain 1->3, 3->4, 4->-1, and 2->-1.


========================================
THEORY: LC496 Why HashMap Is Needed
========================================

Explanation:
The stack discovers answers while processing nums2, but nums1 asks for answers in a different order. A HashMap connects each nums2 value with its computed next greater value.

Example:
This avoids searching nums2 again for every nums1 element.


========================================
THEORY: LC496 Processing nums2 First
========================================

Explanation:
nums2 must be processed before constructing the final nums1 answer because nums2 contains the complete information needed to determine each next greater element.

Example:
Once the map is complete, nums1 can be processed in O(nums1.length).


========================================
THEORY: LC496 Remaining Stack Elements
========================================

Explanation:
After nums2 has been completely processed, values still inside the stack do not have any greater element to their right. Their answer is therefore -1.

Example:
For [4,2], after processing all elements, both unresolved values receive -1.


========================================
THEORY: LC496 Example Walkthrough
========================================

Explanation:
For nums2=[1,3,4,2], start with 1. When 3 appears, pop 1 and record 1->3. Then 3 remains until 4 appears, giving 3->4. The value 2 has no greater value after it, so 2->-1.

Example:
The final map allows direct answers for nums1.


========================================
THEORY: LC496 Complexity
========================================

Explanation:
The monotonic-stack solution runs in O(n+m), where n is nums1.length and m is nums2.length. Each nums2 element is pushed and popped at most once.

Example:
Extra space is O(m) for the stack and HashMap.


========================================
THEORY: LC496 Why Each Element Is Popped Once
========================================

Explanation:
Although there is a while loop inside the main loop, the algorithm is still linear because an element that is popped can never return to the stack.

Example:
Therefore the total number of stack pops is at most nums2.length.


========================================
THEORY: LC496 Common Mistake
========================================

Explanation:
A common mistake is finding any greater element instead of the next greater element. The algorithm must use the first greater value encountered to the right.

Example:
For [2,4,3,5], the answer for 2 is 4, not 5.


========================================
THEORY: LC496 Duplicate Consideration
========================================

Explanation:
The original problem guarantees that nums1 contains unique values and nums2 contains unique values. This allows the answer to be stored directly using the value as a HashMap key.

Example:
If duplicates were allowed, the problem would require additional handling based on positions.
